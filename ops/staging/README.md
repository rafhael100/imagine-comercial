# Comercial SEO-F163 — Container de homologação privado, isolado e sem publicação

Esta configuração prepara uma forma de executar o build Astro no servidor Leaseweb **somente depois que o administrador confirmar acesso e consentir com uma revisão de staging**. Ela não executa comandos Docker, não abre portas no servidor e não instala serviços automaticamente.

Os arquivos estão em `ops/staging/`:

- `compose.yaml`: exige imagem Nginx unprivileged **aprovada e fixada por digest** via `IMAGINE_STAGING_NGINX_IMAGE`, sem imagem padrão. Porta 4321 vinculada **apenas a 127.0.0.1**, sistema de arquivos read-only, processo UID 101, todas as capabilities removidas, `no-new-privileges`, limites de memória/PIDs e volumes de build somente-leitura.
- `nginx.conf`: **exige HTTP Basic** de usuário fixo `reviewer` e senha bcrypt em arquivo externo, além de entregar assets estáticos sem autoindexação, usa 404 customizada, impede métodos que não sejam GET/HEAD, restringe arquivos de configuração e aplica os quatro cabeçalhos defensivos F28, além de **`X-Robots-Tag: noindex, nofollow, noarchive`** e `Cache-Control: no-store` a todas as respostas, inclusive erros. O HTML do build conserva canonical de produção para a futura migração, mas a prévia é **proibida de ser indexada**; esses cabeçalhos não substituem isolamento de rede.

## Procedimento futuro para operador autorizado

1. **Não executar no servidor de produção nem reutilizar dados pessoais.** Preparar um workspace privado/contêiner isolado. Validar o código e o pacote com `npm ci --no-audit --no-fund`, `npm run build` e `node scripts/verify-dist.mjs` antes de copiar artefatos.
2. Selecionar e revisar independentemente um Nginx unprivileged compatível, **fixando a imagem pelo digest real**. Não se deve usar `latest`, tags mutáveis, digest inventado ou credenciais em Git.
3. Criar **fora deste repositório** um único arquivo `.htpasswd` com `reviewer` e hash **bcrypt real** gerado por utilitário confiável (`htpasswd -B -C 12`), com modo `0600` ou `0640`, sem permissão para outros usuários. Verificar que o UID/GID 101 do contêiner tem leitura efetiva do bind mount (por exemplo, grupo 101 e modo `0640`, conforme política da VPS). Definir `IMAGINE_STAGING_HTPASSWD_PATH` como caminho absoluto privado. **Nunca** adicionar o arquivo, seu hash ou a senha ao GitHub, CI, comandos visíveis no histórico ou volume público.
4. Configurar `IMAGINE_STAGING_NGINX_IMAGE` no ambiente privado do operador e executar **primeiro** `IMAGINE_PRIVATE_STAGING_REVIEW=1 node scripts/check-private-staging-prerequisites.mjs`. Antes do comando, o operador também deve fornecer `IMAGINE_EXPECTED_STAGING_TREE_SHA256`, um SHA-256 completo da árvore Astro obtido por **canal de revisão independente** (não confiar cegamente em um manifesto fornecido dentro do pacote que está sendo verificado). A F165 compara cada arquivo do `dist` com esse pin, proíbe symlinks e arquivos publicáveis inesperados e falha se houver até 1 byte divergente. O verificador F164 recusa tags mutáveis, digests de placeholder, build ausente e `_redirects` ou `_headers`, mas **não** verifica assinatura/proveniência real da imagem nem a legitimidade do canal que informou o SHA. Ambas as conferências independentes permanecem obrigatórias. Somente depois usar `docker compose -f ops/staging/compose.yaml config` para revisar volumes e portas antes de **qualquer** inicialização.
5. Apenas com homologação autorizada, iniciar por `docker compose -f ops/staging/compose.yaml up -d --no-build`, verificando que só `127.0.0.1:4321` ficou exposto. Acesso remoto, quando necessário, somente via túnel SSH já autorizado.
6. Fornecer a senha somente por variável segura `IMAGINE_STAGING_REVIEW_PASSWORD` no ambiente efêmero do operador; executar `IMAGINE_PRIVATE_STAGING_REVIEW=1 node scripts/review-private-staging-http.mjs --port=4321`. O ensaio primeiro exige **HTTP 401 sem senha** e depois confere os 22 destinos por Basic Auth. O relatório HTTP F161 deve conferir as quatro páginas e as 18 URLs em HOLD; resultados são revisão, nunca autorização de publicação. Encerrar o container após avaliação.

7. **Alternativa de diagnóstico único:** após todos os pré-requisitos e um contêiner já inicializado pelo operador autorizado, executar `node scripts/review-private-staging-operator.mjs --port=4321` com as cinco variáveis de revisão descritas nas F165–F167. Esse CLI **não** executa Docker, não aprova publicação, não imprime credenciais e é bloqueado no GitHub Actions. Se falhar, o estado continua HOLD.

O HTTP Basic é uma **segunda barreira apenas para staging**, não autentica clientes e não substitui MFA, HTTPS, rede privada ou autenticação do Portal. Só use HTTP em `127.0.0.1` ou através de túnel SSH autorizado, nunca exponha a porta em rede pública. Os segredos e hashes não devem constar de logs, testes de CI nem artefatos.

O Nginx do staging é um **servidor estático de avaliação**, não substitui o runtime final Cloudflare Workerd, nem os testes de assinatura e publicação do Portal/CRM. Faltam acesso Leaseweb, Docker disponível, imagem por digest auditada, revisão independente AppSec/DBA/LGPD, políticas de backup/TLS, permissões, migração e aprovação final de release.
